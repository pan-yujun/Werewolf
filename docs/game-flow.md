## 2. 胜利条件

- **好人胜**：所有狼人死亡（`aliveWolves === 0`）
- **狼人胜**：存活狼人数 ≥ 存活好人数（`aliveWolves >= aliveVillagers`）

胜利条件在**每次有玩家死亡时**都会被检查，包括：夜晚结算后、白天处决后、猎人射击后、白狼王自爆后。

## 4. 夜晚行动阶段

### 4.1 守卫守护

**阶段**: `NIGHT_GUARD_ACTION`

**触发条件**: 场上存在守卫角色（无论存活与否）

**流程**:

```
守卫存在?
├─ 否 → 跳过，随机延迟模拟动画后继续
├─ 人类守卫 → 显示"请选择守护目标"
│  · 等待玩家输入
│  · 验证: 不能连续两晚守护同一人
│  · 输入后 → 继续到狼人阶段
└─ AI守卫 → LLM: generateGuardAction()
   · Prompt构建: NightPhase.buildGuardPrompt()
   · 输入: 角色身份 + 游戏上下文
   · 输出: {"seat": N}
   · 温度: 0.4 (LOGIC)
   · 限制: 排除上一晚的守护目标
   · 解析失败 → 跳过守护
```

**关键文件**: [NightPhase.ts](src/game/phases/NightPhase.ts) `runGuardAction()` 方法

---

### 4.2 狼人刀人

**阶段**: `NIGHT_WOLF_ACTION`

**流程**:

```
有存活的狼人?
├─ 否 → 随机延迟模拟动画后继续
├─ 有人类狼人
│  · 人类狼选择目标
│  · 所有AI狼自动同意人类的选择
│  · 设置 nightActions.wolfTarget
└─ 全AI狼
   · LLM: generateWolfAction()
   · Prompt构建: NightPhase.buildWolfPrompt()
   · 已有的狼票记录会传入 prompt
   · 输出: {"seat": N}
   · 温度: 0.4 (LOGIC)
   · 可选任何存活玩家（含队友，即自刀）
   · 解析失败 → 无人被刀
```

**关键文件**: [NightPhase.ts](src/game/phases/NightPhase.ts) `runWolfAction()` 方法

---

### 4.3 女巫行动

**阶段**: `NIGHT_WITCH_ACTION`

**流程**:

```
女巫存活?
├─ 否 → 跳过
└─ 是 → 检查药水剩余
   ├─ 解药已用 AND 毒药已用 → 跳过
   └─ 有剩余药水
      ├─ 人类女巫
      │  · 显示: 狼刀目标（如有解药）+ 三个选项
      │  · 救人 → 使用解药，wolfTarget 存活
      │  · 毒人 → 选择目标，使用毒药
      │  · 跳过 → 不做任何操作
      └─ AI女巫
         · LLM: generateWitchAction()
         · Prompt包含: 狼刀目标信息
         · 输出: {"action": "save"} / {"action": "poison", "seat": N} / {"action": "pass"}
         · 温度: 0.4 (LOGIC)
         · 解药限制: witchHealUsed = false 且有狼刀目标
         · 毒药限制: witchPoisonUsed = false
         · 每种药水整局仅限一次
         · 解析失败 → 不行动（pass）
```

**药水消耗规则**:
- 使用解药后 `witchHealUsed = true`
- 使用毒药后 `witchPoisonUsed = true`
- 两种药水独立计数，各限一次

---

### 4.4 预言家查验

**阶段**: `NIGHT_SEER_ACTION`

**流程**:

```
预言家存活?
├─ 否 → 跳过
└─ 是
   ├─ 人类预言家
   │  · 选择查验目标
   │  · 立即看到结果（狼阵营 / 好人阵营）
   │  · 结果存入 seerHistory[]
   │  · 流程暂停，等待玩家点击继续
   └─ AI预言家
      · LLM: generateSeerAction()
      · 输出: {"seat": N}
      · 温度: 0.4 (LOGIC)
      · 结果: 目标是否为狼阵营
      · seerHistory[] 避免重复查验已知身份
      · 解析失败 → 不查验
```

### 4.5 夜晚结算

**阶段**: `NIGHT_RESOLVE`

这是夜晚最复杂的阶段，涉及**三重保护交互**和**毒药独立结算**。

#### 狼刀结算（三重保护交互）

```
┌─────────────────────────────────────────────────────────────┐
│                    狼刀目标 vs 保护措施                       │
│                                                             │
│  守卫守护了狼刀目标?                                         │
│  ├─ 是                                                      │
│  │  └─ 女巫也救了狼刀目标?                                   │
│  │     ├─ 是 → ❌ 双重保护 = 人死亡！（奶守同守规则）        │
│  │     └─ 否 → ✅ 仅守卫保护 = 人存活                       │
│  └─ 否                                                      │
│     └─ 女巫救了狼刀目标?                                     │
│        ├─ 是 → ✅ 仅女巫救人 = 人存活                       │
│        └─ 否 → ❌ 无保护 = 人死亡（狼刀成功）               │
└─────────────────────────────────────────────────────────────┘
```

> **重要规则**: 守卫守护 + 女巫救人同时作用于同一目标时，**双重保护反而导致死亡**（奶守同守）。这是经典狼人杀的平衡规则。

#### 毒药结算

```
┌─────────────────────────────────────────────────────────────┐
│  女巫使用了毒药?                                             │
│  ├─ 是 → 目标必死（无论是否有其他保护）                      │
│  │       · 毒杀的猎人不能射击（毒杀禁用猎人技能）            │
│  └─ 否 → 无毒药效果                                         │
└─────────────────────────────────────────────────────────────┘
```

#### 死亡处理

- 死亡信息**不在夜晚公布**，存入 `pendingWolfVictim` 和 `pendingPoisonVictim`
- 留到 `DAY_START` 阶段统一公布
- 如果狼刀目标和毒药目标是同一人，只记录一次死亡

## 5. NIGHT_START 阶段详解

### 5.1 角色揭示

仅在游戏的**第一个夜晚**执行 `revealRoles()`，向每位玩家揭示其角色身份。后续夜晚跳过此步骤。

### 5.2 每日摘要生成

从第2个夜晚开始，`NIGHT_START` 会在进入夜晚行动前，调用 `maybeGenerateDailySummary()` 为**刚刚过去的那个白天**生成一份结构化摘要。

#### 为什么需要这个？

狼人杀是一个多回合的推理游戏。随着天数增加，AI 玩家需要记住之前每天发生了什么（谁说了什么、谁投了谁、谁声称是什么身份）。直接把所有历史发言塞进 prompt 会超出上下文窗口，所以系统用 LLM 把每天的关键信息压缩成 6-12 条要点，作为**长期记忆**注入后续回合的 prompt。

#### 生成流程

```
NIGHT_START
  │
  ├─ day <= 0? → 跳过（第1天还没开始，没有白天记录）
  │
  ├─ 今天已有摘要? → 跳过（避免重复生成）
  │
  └─ 调用 generateDailySummary(state)
       │
       ▼
     ┌─────────────────────────────────────────────┐
     │ 1. 收集当天白天的所有消息                      │
     │    · 从最后一条 "天亮了" 系统消息开始           │
     │    · 到 "投票开始" 系统消息为止                 │
     │    · 包括系统公告 + 所有玩家发言               │
     │    · 格式化为: "3号 张三: 我是预言家..."        │
     │    · 截断到 15000 字符                         │
     └──────────────────────┬──────────────────────┘
                            ▼
     ┌─────────────────────────────────────────────┐
     │ 2. 同时提取投票数据                           │
     │    extractVoteDataFromDayMessages()           │
     │    · 解析 [VOTE_RESULT] 系统消息               │
     │    · 警长选举: 谁当选、每人得票                 │
     │    · 处决投票: 谁被投出、票数分布               │
     └──────────────────────┬──────────────────────┘
                            ▼
     ┌─────────────────────────────────────────────┐
     │ 3. 构建 LLM 请求                              │
     │                                               │
     │ System Prompt (中文):                         │
     │ "你是狼人杀客观记录员。                        │
     │  任务：将当天白天记录压缩为要点列表，          │
     │        作为后续回合的长期记忆。                │
     │                                               │
     │  核心原则                                      │
     │  - 客观记录每位玩家说了什么、做了什么          │
     │  - 保留原始观点和立场，不加主观判断            │
     │  - 只记录事实，避免推测性因果                  │
     │                                               │
     │  必须包含（全部必填）                          │
     │  1. 昨夜结果：平安夜/谁出局/死因               │
     │  2. 警长结果：谁竞选、谁当选、得票             │
     │  3. 身份声明：谁声称什么身份、报了什么查验     │
     │  4. 每位发言玩家的核心观点（每人1句话）        │
     │  5. 站边关系：谁支持谁、谁质疑谁               │
     │  6. 投票结果：谁被放逐、票数分布               │
     │                                               │
     │  格式要求                                      │
     │  - 必须包含座位号                              │
     │  - 每条要点简短                                │
     │  - 需要6-12条要点                              │
     │  - 确保每位发言玩家都被记录                    │
     │                                               │
     │  输出：{ \"bullets\": [\"要点1\", ...] }"     │
     │                                               │
     │ User Prompt:                                  │
     │ "【第2天 白天记录】                            │
     │  3号 张三: 我是预言家，昨晚查验了5号是好人     │
     │  5号 李四: 3号在撒谎，我才是真预言家           │
     │  ..."                                         │
     │                                               │
     │  严格返回 JSON："                              │
     └──────────────────────┬──────────────────────┘
                            ▼
     ┌─────────────────────────────────────────────┐
     │ 4. LLM 调用配置                               │
     │    · 模型: SUMMARY_MODEL (专用摘要模型)        │
     │    · Temperature: 0.1 (极低，追求客观稳定)     │
     │    · response_format: json_object              │
     │    · 重试: 最多2次，失败后附加重试指令         │
     └──────────────────────┬──────────────────────┘
                            ▼
     ┌─────────────────────────────────────────────┐
     │ 5. 解析响应                                   │
     │    · 期望: {"bullets": ["要点1", "要点2", ...]}│
     │    · 兼容: {"summary": "..."} 单条摘要        │
     │    · 最终 fallback: 直接用原始文本             │
     └──────────────────────┬──────────────────────┘
                            ▼
     ┌─────────────────────────────────────────────┐
     │ 6. 存入 GameState                             │
     │    · state.dailySummaries[day] = bullets[]    │
     │    · state.dailySummaryVoteData[day] = voteData│

```

#### 摘要如何被使用

生成的摘要不会直接展示给玩家，而是注入到后续回合的 **AI 角色 prompt** 中。每个 AI 玩家在做决策（发言、投票、夜间行动）时，都能看到这份压缩后的历史记忆：

```
【历史关键信息】
第1天: 3号声称预言家，查验5号为好人
第1天: 5号反驳3号，自称真预言家
第1天: 7号被投票出局，得票: 2号、4号、6号
第2天: 平安夜，无人死亡
```

从而做出有连贯性的推理。

#### 为什么 Temperature 只有 0.1？

摘要任务的目标是**客观记录事实**，不需要创意。极低的 temperature 确保：
- 每次生成的摘要内容一致
- 不会添加主观判断（如"3号可能是狼"）
- 严格遵循"记录说了什么"而非"推测为什么"

#### 投票数据的特殊处理

除了文字摘要，系统还单独提取结构化的投票数据（`DailySummaryVoteData`），包含：
- `sheriff_election`: 警长选举的得票明细（winner + votes map）
- `execution_vote`: 处决投票的票数分布（eliminated + votes map）

这些数据用于在后续 prompt 中构建更精确的投票历史表格，让 AI 玩家能分析"谁投了谁"的模式。

- [game-master.ts:646](src/lib/game-master.ts#L646) `generateDailySummary()` 函数

## 12. LLM 调用详细拆解

> 所有函数定义在 [src/lib/game-master.ts](src/lib/game-master.ts)。Prompt 模板来自 [src/i18n/messages/zh.json](src/i18n/messages/zh.json)。上下文构建工具在 [src/lib/prompt-utils.ts](src/lib/prompt-utils.ts)。

### 架构模式

所有 LLM 调用遵循两种模式之一：

- **模式 A（PhaseManager 委托）**: 函数调用 `resolvePhasePrompt()` → `PhaseManager.getPrompt()` → 对应 `GamePhase` 子类的 `getPrompt()` 方法，返回 `{ system, user, systemParts }`，再由 `buildMessagesForPrompt()` 转为 `LLMMessage[]`
- **模式 B（直接构建）**: 函数自行构建 `messages` 数组，绕过 PhaseManager

`buildMessagesForPrompt()` 始终产出两条消息：一条 system message（可能带 `cache_control` 缓存断点）和一条 user message。

## 13. 完整游戏循环

```
═══════════════════════════════════════════════════════════════
  第1夜
═══════════════════════════════════════════════════════════════

  NIGHT_START
    → 角色揭示
    → NIGHT_GUARD_ACTION    [LLM: 守卫选人守护]
    → NIGHT_WOLF_ACTION     [LLM: 狼人选人刀杀]
    → NIGHT_WITCH_ACTION    [LLM: 女巫救人/毒人/跳过]
    → NIGHT_SEER_ACTION     [LLM: 预言家选人查验]
    → NIGHT_RESOLVE         [结算: 计算存活/死亡]

═══════════════════════════════════════════════════════════════
  第1天 (含警长竞选)
═══════════════════════════════════════════════════════════════

  DAY_START
    → DAY_BADGE_SIGNUP      [LLM: 批量决定是否参选]
    → DAY_BADGE_SPEECH      [LLM: 候选人发言, 可能WWK自爆]
    → DAY_BADGE_ELECTION    [LLM: 非候选人投票]
    → (平票? → DAY_PK_SPEECH → 重投)
    → 死亡公布              [公布夜间的死亡]
    → (猎人死亡? → HUNTER_SHOOT [LLM: 猎人射击])
    → (警长死亡? → BADGE_TRANSFER [LLM: 警徽流传])
    → DAY_SPEECH            [LLM: 每人发言, 可能WWK自爆]
    → DAY_VOTE              [LLM: 每人投票]
    → DAY_RESOLVE           [计票 → 处决/平票PK/无人出局]
    → (白痴首次被投? → 存活但失去投票权)
    → (猎人被处决? → HUNTER_SHOOT)
    → (警长被处决? → BADGE_TRANSFER)
    → DAY_LAST_WORDS        [LLM: 被处决者遗言]
    → 胜利条件检查

═══════════════════════════════════════════════════════════════
  第2夜
═══════════════════════════════════════════════════════════════

  NIGHT_START [LLM: 生成每日摘要]
    → 守卫 → 狼人 → 女巫 → 预言家 → 结算
    → (猎人/警长死亡? → 特殊事件)
    → 胜利条件检查

═══════════════════════════════════════════════════════════════
  第2天 (无警长竞选)
═══════════════════════════════════════════════════════════════

  DAY_START
    → 死亡公布
    → (猎人/警长死亡? → 特殊事件)
    → DAY_SPEECH            [LLM: 发言, 可能WWK自爆]
    → DAY_VOTE              [LLM: 投票]
    → DAY_RESOLVE
    → DAY_LAST_WORDS
    → 胜利条件检查

═══════════════════════════════════════════════════════════════
  ... 循环直到胜利条件满足 ...
═══════════════════════════════════════════════════════════════

  GAME_END
    → LOBBY (返回大厅)
```

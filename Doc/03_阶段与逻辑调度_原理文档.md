# 模块 03 - 阶段管理与游戏引擎 - 原理文档

狼人杀本质上是一个多分支且包含复杂异步回调的有限状态机 (FSM)。Wolfcha 采用多态映射（PhaseManager）配合中央编排器（useGameLogic）的混合架构，完成了清晰的阶段切分和高弹性的逻辑流动。

---

## 一、 狼人杀有限状态机模型 (FSM Mode)

Wolfcha 的所有游戏逻辑推进和 UI 动态展示均基于当前的状态阶段枚举 `Phase`（定义于 `src/types/game.ts`）。

### 1.2 边缘事件状态抢占 (State Preemption)
除了上述的主流程外，状态机还必须能随时挂载和处理三种高优先级的边缘抢占状态：
1.  **猎人射击 (HUNTER_SHOOT)**：当猎人因夜间被刀或白天被投出局（且非女巫毒杀），状态机会被强行抢占，等待射击决策。
2.  **警徽移交 (BADGE_TRANSFER)**：当持警徽者死亡时，流程挂起，由死者决定传徽或撕徽。
3.  **白狼王自爆 (WHITE_WOLF_KING_BOOM)**：在白天发言的任何空档，白狼王可随时抢占状态机强行起爆，直接带走一名玩家并宣告白昼立刻终止，跳过投票直接切回夜晚。

## 二、 阶段提示词管理器 (PhaseManager)

为了防止提示词构建规则（如“预言家怎么看到自己的查验历史”、“守卫怎么排除昨晚守护”）污染业务层，系统引入了多态设计的 **PhaseManager**。

*   **设计原则**：每个阶段都具有唯一的类职责。
*   **接口标准化**：基础抽象类 `GamePhase` 提供契约，子类必须实现 `getPrompt(context, player)`，以便在为 AI 玩家发起 LLM 请求时，根据其特定的角色人设、游戏记忆、存活状态组装成特定的 System 和 User Prompt 字符串。

---

## 三、 主逻辑编排器 (`useGameLogic`) 与子 Hook 的时序编排

主 Hook `useGameLogic` 充当了“调度总线（Central Dispatcher）”，由于其体积庞大，为了便于维护，将白天、警长竞选和特殊决策切分为三个专职子 Hook：
1.  `useDayPhase`：驱动白天发言顺序算法，管理 AI 发言的预取（Prefetching）、流式 SSE 输出及其 TTS 的同步加载。
2.  `useBadgePhase`：协调复杂的竞选表决、平票重投和警徽在人机之间的流转。
3.  `useSpecialEvents`：处理夜晚奶守同死规则的交叉结算、死因归纳以及检测是否满足好人或狼人的终极胜利条件。

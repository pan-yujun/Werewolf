# 项目结构说明

Wolfcha 是一款 AI 驱动的狼人杀（社交推理）游戏，基于 Next.js 16 App Router 构建。所有非人类玩家均由 LLM 控制。

## 核心模块说明

### 游戏状态管理

**文件**: `src/store/game-machine.ts`

使用 Jotai atoms 管理游戏状态：
- `gameStateAtom` — 游戏状态的单一数据源
- 持久化到 `localStorage`（24 小时 TTL），支持页面刷新恢复

### 游戏逻辑层

| 层 | 文件 | 职责 |
|----|------|------|
| Game Master | `src/lib/game-master.ts` | 纯函数：玩家设置、阶段转换、胜负判定、击杀解析 |
| Flow Controller | `src/lib/game-flow-controller.ts` | `AsyncFlowController` — 中断/暂停/恢复异步游戏流程；`FlowToken` 模式防止过期回调 |
| Phase Manager | `src/game/core/PhaseManager.ts` | 将每个 `Phase` 枚举值映射到 `GamePhase` 类，生成 LLM 提示词 |
| Game Phases | `src/game/phases/` | 各阶段类：`NightPhase`, `DaySpeechPhase`, `VotePhase`, `BadgePhase`, `HunterPhase`, `WhiteWolfKingBoomPhase` |
| Game Logic Hook | `src/hooks/useGameLogic.ts` | React hook，编排完整游戏循环，委托给子 hook |
| Phase Sub-hooks | `src/hooks/game-phases/` | `useDayPhase`, `useBadgePhase`, `useSpecialEvents` |
| Dialogue Manager | `src/hooks/useDialogueManager.ts` | 流式 AI 发言管理、打字机效果 |

### 游戏阶段（Phase 类型）

**文件**: `src/types/game.ts`

```
夜晚: NIGHT_START → NIGHT_GUARD_ACTION → NIGHT_WOLF_ACTION → NIGHT_WITCH_ACTION → NIGHT_SEER_ACTION → NIGHT_RESOLVE
白天: DAY_START → DAY_BADGE_SIGNUP → DAY_BADGE_SPEECH → DAY_BADGE_ELECTION → DAY_SPEECH → DAY_VOTE → DAY_RESOLVE
特殊: HUNTER_SHOOT, WHITE_WOLF_KING_BOOM, BADGE_TRANSFER, GAME_END
```

### AI 集成

- 所有 LLM 调用通过 `/api/chat` 路由代理
- 支持 ZenMux、Dashscope、Mimo、Modelscope、Volcengine（火山引擎）等 Provider
- 模型注册在 `src/types/game.ts` 的 `ALL_MODELS` 和 `PROJECT_MODELS`
- 每个阶段的提示词由 `GamePhase` 子类的 `getPrompt()` 生成
- `src/lib/llm.ts` — 底层流式 fetch 辅助
- `src/lib/character-generator.ts` — AI 角色人设生成
- `src/lib/ai-config.ts` — 模型角色路由（GENERATOR / SUMMARY / REVIEW）

### FlowToken 模式

在任何异步操作前，捕获 `flowController.getToken()`。`await` 之后调用 `token.isValid()` 检查流程是否被中断（如游戏重置中途回调）。

---

## 关键约定

1. **FlowToken 模式**: 异步操作前后检查 token 有效性
2. **阶段提示词**: 新增阶段需创建/扩展 `GamePhase` 子类，并在 `PhaseManager` 注册
3. **模型路由**: 内置模型使用 ZenMux/MiMo，用户自定义 Key 走 Provider 专属路径（见 `src/lib/api-keys.ts`）
4. **新增 Provider 流程**: `ModelRef.provider` 联合类型 → `MODEL_IDS`/`ALL_MODELS` → `api-keys.ts` get/set/has → `llm.ts` header → `chat/route.ts` 分支 → `validate-key`/`list-models`/`verify-models` → `UserProfileContent.tsx` UI → `character-generator.ts` → i18n
5. **包管理器**: 使用 pnpm

## LLM Provider 配置参考

### 火山引擎（Volcengine Agent Plan）

| 项目 | 说明 |
|------|------|
| Provider ID | `"volcengine"` |
| API Base URL | `https://ark.cn-beijing.volces.com/api/plan/v3`（可通过 `VOLCENGINE_BASE_URL` 环境变量覆盖） |
| 认证方式 | Bearer Token（`Authorization: Bearer <API_KEY>`） |
| 环境变量 | `VOLCENGINE_API_KEY` + `VOLCENGINE_BASE_URL` |
| 客户端 Header | `X-Volcengine-Api-Key` |
| 验证模型 | `deepseek-v4-flash`（`VOLCENGINE_VALIDATION_MODEL`） |
| 可用模型 | `deepseek-v3.2` / `deepseek-v4-flash` / `deepseek-v4-pro` / `minimax-m2.7` / `minimax-m3` / `glm-5.1` / `kimi-k2.6` / `doubao-seed-2.0-code` / `doubao-seed-2.0-pro` / `doubao-seed-2.0-lite` / `doubao-seed-2.0-mini` |
| 特殊说明 | Agent Plan 的 `/models` 接口返回 404，"获取模型列表"功能不可用；模型池在 `ALL_MODELS` 中硬编码 |
| 涉及文件 | `types/game.ts` · `lib/api-keys.ts` · `lib/llm.ts` · `lib/character-generator.ts` · `api/chat/route.ts` · `api/validate-key/route.ts` · `api/list-models/route.ts` · `api/verify-models/route.ts` · `components/game/UserProfileContent.tsx` · `i18n/messages/zh.json` · `i18n/messages/en.json` |
